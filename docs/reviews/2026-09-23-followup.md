# Review follow-up: working tree after 861e93e

Date: 2026-09-23. This follows the [review of 861e93e](2026-09-22-review-861e93e.md). It describes the current working tree, not a released version.

## Addressed here

| Prior finding | Change and check |
|---|---|
| C1: all-views isolation theorem does not express caller privacy | Added `ScopedApp.CallerObligations` and `step_noninterference_caller`; proved them for private-games and notes-with-sharing. The original all-views theorem remains for its stronger premise. `EVIDENCE.md`, README and decision 0015 state the actual scopes. A successor-view theorem under only one caller's view is still open. |
| C2: huge HTTP ids wrap into SQLite ids | `PlayerId.make` and `GameId.make` now reject ids outside 1 through 2^63−1; HTTP regression tests cover an aliasing opponent id and game id. Direct construction of these plain newtypes inside trusted code is still possible, so the repository boundary is not fully type-safe. |
| H1: dummy scrypt eliminated by compiler | The unknown-user branch now consumes the verification result in IO. Generated C contains `LeanCrypto_Password_verify` in both known and unknown branches. |
| H2: wildcard CORS plus credentials | The combination now denies cross-origin access; regression test checks no `Access-Control-Allow-Origin` is emitted. |
| H3: proxy header spoofing | `trustedProxy` selects one header family. Default is `X-Forwarded-For`; deployments whose proxy appends RFC `Forwarded` opt into `.forwarded`. Tests cover spoofed `Forwarded` beside trusted XFF and the opt-in chain. Correctness still depends on the configured proxy appending or replacing its chosen header. |
| H4: evidence scope | `EVIDENCE.md`, the decision record and changelog now distinguish immediate successful keyed replay from unproved replay after intervening requests and distinguish checked key reuse from a theorem. |
| Snapshot gap: list count and page could disagree | A deferred transaction covers both SQL statements on the same reader connection. A deterministic test commits a new game between count and page and verifies one snapshot. |
| M2: post-handler 412 could hide a write | `conditionalGet` now only handles safe GET/HEAD requests. `checkIfNoneMatch` is a pre-write helper. A test exercises both paths and checks the write count. |

## Still open

- Native/model refinement is checked only by a bounded differential test; it is not proved. The test's request and header coverage is narrower than the full route surface.
- A timeout can return 504 while an admitted command later commits. Decision 0008 now says so. A stronger cancellation or outcome protocol remains to be designed.
- `Runtime.writeConn` and `readConns` remain public, so trusted code can bypass the scoped repository. Directly constructed out-of-range ids are not ruled out by the type system.
- The prior review's remaining HTTP findings (encoded slashes, SSE and multipart parsing, cookie attributes, content negotiation) and unbounded request threads remain open.
- CI execution for this working tree has not been verified. Local checks: `lake build leanapi_tests`, `lake build notes games`, 250 tests passed, axiom audit passed for 46 theorems, and `git diff --check` passed.
